# Decision log (orchestrator)

Brief said: no questions, resolve every ambiguity and log it.

1. **Motion engine.** The reference pages do not expose GSAP timelines: they run Webflow IX2 interactions, Lottie (bodymovin) loops, Swiper, `<video>` loops and a small bundled gsap chunk on the home page. All motion is re-implemented in GSAP + ScrollTrigger here, taking triggers, durations, easings and staggers from the reference's IX2 data / scripts (downloaded to `/home/claude/ref/<page>/js-*`).
2. **Copy conflict.** The brief says both "Lorem Ipsum" and "copy from rebirthwebdesign.com.au". Resolution: Rebirth copy (saved in `docs/source-copy.md`) is fitted to each section first; Lorem Ipsum only fills slots with no fitting source text. Text length is kept close to the reference so line breaks and block heights match.
3. **Style doc placement.** `DESIGN.md` → `docs/DESIGN.md` (governs every design decision). `theme.css` → `src/styles/theme.css` (Tailwind v4 `@theme`, imported right after `tailwindcss`). `variables.css` → `src/styles/variables.css` (`:root`). `tokens.json` → `src/tokens/tokens.json` (source of truth for token values). All four are unmodified copies.
4. **Fonts.** ABC Ginto Discord / Nord are proprietary. The substitutes named in DESIGN.md (Unbounded for Nord, DM Sans for the body face) are self-hosted and registered under the documented family names so the tokens stay untouched. Glyph widths therefore differ from the reference.
5. **Brand assets.** No Discord logo, wordmark, mascots/characters (Wumpus, Clyde, etc.), product screenshots or any file downloaded from the reference is used. The site is branded Rebirth Web Design with original graphics, per the brief's "custom graphics" + "Unsplash only" rules.
6. **QA tooling.** Playwright (headless Chromium in the build sandbox) is used for all reference comparisons instead of Claude in Chrome — same result, no load on the team's browser.
7. **What "replica %" measures.** Copy, photos, illustrations and fonts are different by brief, so a pixel diff against the reference cannot approach 99%. Fidelity is measured on what the brief says must match: section geometry (positions/sizes at 1680px), typography metrics, colour, radii, spacing and motion parameters.
8. **Viewport.** 1680px desktop is the measured target (the style docs' viewport). Layouts must also hold at 1280, 768 and 390 following the reference's own responsive behaviour.
9. **Careers.** The whole job-listing section headed "DON'T JUST IMAGINE THE FUTURE OF GAMING — BUILD IT WITH US." (reference y≈3172–9889) is omitted as instructed.
10. **Links.** Nav/footer links to pages outside the five built pages point to `#`.
11. **Photos.** Unsplash photos are downloaded into `src/assets/photos/` (served through Astro's image pipeline) and credited in `docs/CREDITS.md`. Where the reference shows product UI inside a media inset, an Unsplash photo and/or an original UI-style graphic is used on the same gradient fill.
12. **Canvas colour off the home page.** The style docs give Deep Indigo `#1a2081` as the canvas but were sampled on the home page only. The reference download and quests pages measure black with blurple glows, so those pages use black (`--color-black` token). Home keeps Deep Indigo.
13. **Per-page metrics the docs did not sample.** Download/quests headings (72px and 48px, tighter tracking) and their compact 48–52px buttons use measured reference values, since those elements do not exist on the home page the docs were taken from.
14. **Measured exceptions to the docs' "no shadows / no borders" rule.** Kept only where the reference measurably has them on states or elements the docs did not sample (button hover shadows, menu divider lines, a tablet button ring). Each is noted in the owning component.
15. **Preview pages.** Per-section preview pages moved to `tools/previews/` so they are not part of the production build.
16. **Generic star layers removed** from the home and quests heroes during QA (the reference heroes carry only their measured twinkle stars / none); the page starfield was retuned to the reference's dim lavender tone.
17. **Fluid, rem-based type tokens (2026-11-21).** Type sizes moved from px to `rem` so they follow the visitor's browser text-size setting. The four display sizes use `clamp()`: display 36→56px, heading-lg 32→48px (full at 1280), heading 27→36px, marquee 47→61px, ramping from 768px to full size at 1440px. Heading tracking is now -0.01em (scales with size). `--tracking-button` stays 0.25px (controls keep fixed sizes). Spacing, radii and control heights stay px. Verified: section geometry on all five pages unchanged at 1680/1440/1280/1024/768/390 versus the previous build. The quests hero h1 is pinned to 3.5rem because the reference keeps it 56px down to 768px. Component-level px font sizes (about 150 declarations, mostly breakpoint overrides) are unchanged.
18. **Foundations wave (2026-11-21).** Added `tsconfig.json` (strict preset, `@components` / `@layouts` / `@lib` / `@data` / `@islands` / `@styles` / `@assets` aliases), `astro check`, ESLint (flat config) and Prettier, then formatted the repo once. Added `@astrojs/react`, `@astrojs/sitemap` and the `@astrojs/cloudflare` adapter (pages stay prerendered; on-demand rendering is opt-in per route), with `site` set to `https://rebirthwebdesign.com.au`. `BaseLayout` now emits canonical, Open Graph, Twitter and theme-color tags, and `public/` has an SVG favicon and `robots.txt`. Fonts are imported from the `@fontsource-variable` packages instead of copies in `src/assets/fonts`. `qa-tools/` moved to `tools/qa/`, `AGENTS.md` replaced by `CONTRIBUTING.md`, and a CI workflow runs check, lint, format:check and build. No visual or behavioural change; section geometry and screenshots verified against the pre-restructure baseline.
19. **Structure wave (2026-11-21).** Routes renamed: `/download` → `/services`, `/nitro` → `/plans`, `/ads/quests` → `/launch`; the old URLs are 301 redirects (`redirects` in `astro.config.mjs`, emitted to `_redirects` by the Cloudflare adapter). Components moved into `ui/`, `layout/`, `graphics/{objects,loops,characters,mocks,icons}/` and `sections/<page>/`; `carousel.ts` moved to `src/lib/`. Files, components, CSS classes, ids, data attributes and script selectors were renamed to content-based names with one convention: the block is the component's kebab-case name (`PlansHero` → `.plans-hero`, `.plans-hero__title`, `.plans-hero--x`); page-level shared layers use the page name (`.plans-page`, `.launch-wrap`). The abbreviated prefixes (`nh`, `np`, `q-`, `fa-`, `rb-`, and so on) are gone. `data-section` values and `data-nav-trigger` were deliberately not renamed because the regression gate keys on them, so some still read `nitro-*`, `quests-*` and `download-*`. Photos were renamed to the new page names. CI now runs on `push` to `main` and on `pull_request`. No visual or behavioural change; section geometry and screenshots verified against the baseline.
20. **Motion module wave (2026-11-21).** All GSAP setup moved to `src/lib/motion.ts`: plugins are registered once, the four cubic-bezier curves in use are registered once as `ease.css`, `ease.in`, `ease.inOutSine` and `ease.outQuart` (the CSS `ease` curve had been registered under five different names; none of GSAP's built-in eases is mathematically identical to any of the four, so all stay custom), and the reduced-motion and breakpoint queries are constants. Components start animation with `motion()` (a `gsap.matchMedia()` scoped to the section, so one revert undoes everything it created) or `media()` for non-motion-gated work, and wrap their script in `onPage()`, which is written to re-run on `astro:page-load` and revert on `astro:before-swap` once the client router is enabled. `playWhileInView()` replaces seven identical in-view play/pause triggers. `Draggable` stays out of the module so pages without carousels do not ship it; it is registered in `src/lib/carousel.ts` and in `LaunchStories` until the two carousel engines merge. Fixed on the way: the three home media loops listened for `fb:enter` / `fb:leave` events that the structure wave had renamed, so they never played; they now use `playWhileInView()` on their feature block and the event and `data-inview` attribute were removed. The plans FAQ passed an unparsable `cubic-bezier(...)` string as an ease, which GSAP silently resolved to `power1.out`; it now says `'power1.out'` explicitly. The footer language select's `aria-labelledby` pointed at an id the structure wave had renamed. No other motion parameter changed.
21. **UI primitives wave (2026-11-21).** One `ui/Button`, one `layout/Section` and one `ui/Heading` replace the per-page copies, and the last `is:global` styles and `!important` overrides are gone.
    - **Button scale.** `size` is `nav` (39px), `sm` (40px, 14/500, 16px side padding), `md` (48px), `lg` (56px, 16/500, 24px side padding) or `xl` (56px, 18/400; 65px, 20/400 from 1440px). `variant` is `white`, `blurple` or `ghost`; `glow` adds the hover glow (one script, 200ms linear); `block` fills the parent. ServicesButton, CareersGlowButton, LaunchButton and the `.plans-btn` rules are deleted. Buttons whose old height or padding differed by a few pixels from the nearest step were snapped to it, which moved the sections that contain them by that amount; the per-width differences were reviewed and re-baselined at the Button checkpoint. The plans compare-table buttons use `sm` so they fit the 108px plan columns at 390px.
    - **One gutter schedule.** `Section` pads its content 6vw, 40px from 480px, 80px from 992px and 120px from 1440px, in a 944px container that becomes 1200 (`narrow`), 1538 (`wide`) or 1800 (`ultra`) from 1440px; `padding="section"` adds 50/60/80px of vertical padding. Pages that used slightly different gutters (the careers sections in particular) moved to this schedule, which shifted their content by a few pixels at some widths. Hero sections, the launch subnav, logos and CTA and all home sections keep their own geometry (see CONTRIBUTING).
    - **Heading scale.** `size` is `xl` (9.75vw, 3.5rem from 480px, 4.5rem from 1440px; line height 1, then 0.9 from 1440px), `lg` (8.2vw, 2.5rem, 3rem), `md` (1.5rem, 2rem, 2.25rem) or `sm` (1.25rem, 1.625rem, 1.75rem). Tracking is in em (-0.03, -0.02, -0.01 and -0.01em). Step changes are at 480px and 1440px for every page. Pixel changes it caused: h2 tracking went from -0.01em to -0.02em (0.013% of plans-1680 and 0.062% of launch-390 differ); the launch steps h3 is 26px from 480 to 1439px (was 32px), which shortens each step card by 6px at 768px; two launch h2s that took 3 and 2 lines at 768px take 2 and 1; "Edge-delivered" on services at 390px takes 1 line (was 2); the services banner h2 and the careers CTA h2 are 38px at 390px (were 32px), 12px taller each. `Heading` has no margin or alignment; sections add those through `class`.
    - **FeatureBlock** takes `tightGutter` and `slabTexture` props instead of the cross-file `tight-gutter` selector. **Header** is split into `Header`, `HeaderDropdown` and `MobileMenu`, with links in `src/data/navigation.ts`; the dead `is-scrolled` toggle is removed.
    - **Plans compare table.** The group title (now an h4) spans the full row. Below 768px the two plan columns are 108px (they were 192px from 480px, which collapsed the label column to 0px at 480px and to under 120px up to 620px); at 390px the group rows are 96px shorter. Row labels use `overflow-wrap: break-word`, plus `hyphens: auto` below 390px only, and the label no longer shrink-wraps its text (the flex declarations were dropped). Known and left: home "Always have something new" overflows its box by 9px at 320px, and plans "Faster pages" extends 24px past the viewport at 480 to 500px; both were already so.
22. **Wave 5 carousel autoplay (2026-11-24).** Wave 5b (`01ed127`) held carousel autoplay while the carousel was off screen. The original runs the 9s countdown from page load and pauses only on hover, so the motion gate failed on `careers/careers-party` (11 -> 0). Reverted in 5c (`fb71bca`): autoplay ignores visibility again; the IntersectionObserver now only gates arrow-key handling. Fidelity to the original wins. VPS gate (2026-11-24): layout baseline recorded on `fb71bca`, verify noise 0.000% over two runs; the committed motion baseline passes on the VPS unchanged.
23. **Wave 6 graphics (2026-11-24).** Stars: `graphics/stars/` holds `Starfield` (moved unchanged) and one `Twinkles` (typed `origin`, `sparkle`, `blur`, `play`) built on `lib/twinkle.ts`; `FeatureStars` is gone. The home hero and closing banner keep their own stars because their eases (custom `ease.in` vs `power1.in`), sequences and triggers differ, and merging them would change motion. Parallax: `ParallaxFloat` became `graphics/Parallax.astro` on `lib/parallax.ts` (`parallax(el, options)`); only exact fits were migrated (PlansFaq, PlansCompare, PlansCta). Kept as is: sections whose parallax is an offset keyframe inside a timeline (launch hero/platform/CTA, services hero, plans hero/tiers/explore, careers hero/values), FeatureBlock (computed trigger zone), FeatureObjects (`motion(document.body)` stagger), CareersCta (migration dropped its motion count 12 -> 10), and ServicesBanner (its resting `y:-100` set would be cleared by the wrapper's cleanup). Per-page object components stay art plus their own motion; splitting them further would mean special-case wrapper options.
24. **Wave 7 content (2026-11-24).** Copy moved from section frontmatter into typed, readonly `src/data/` files: `site.ts` (name, URL, default description, footer languages and social labels; `astro.config.mjs` reads `site.url` from it), `pages.ts` (per-route title and description; `BaseLayout` takes `page`), `faqs.ts`, `plans.ts`, `slides.ts`, and per-page `launch.ts`, `careers.ts`, `services.ts` for content that fits none of the five planned kinds. Data keys are descriptive (`title`, `text`, `value`, `image`). No `features.ts`: the home feature copy is slot markup with inline `<br>`, so it stays in the components. Layout values (positions, star coordinates) stay in components. Rendered HTML is unchanged except four new meta descriptions (home, services, careers, launch), each composed only from copy already on that page; listed in `docs/QA-REPORT.md` for the user to review.
